# Список задач через nginx

Практическая работа от 05.11.2026 по разработке клиент-серверных систем.
Nginx раздаёт HTML, CSS и JavaScript, а запросы API направляет приложению FastAPI.
Форма добавляет задачи через `fetch()` без перезагрузки страницы.

## Запуск в Linux

Нужны Python 3.12, uv и nginx. Для Ubuntu nginx устанавливается командой
`sudo apt install nginx`. Далее из корня репозитория:

```bash
cd labs/tasks-nginx
uv sync --locked
bash start_api.sh
```

Во втором терминале из той же папки:

```bash
bash start_nginx.sh
```

Страница открывается по адресу http://localhost:8085. Nginx слушает порт 8085,
а приложение доступно только на 127.0.0.1:8005. Порт 80 и системная конфигурация
nginx для этого запуска не используются. Остановка каждого процесса: Ctrl+C
в соответствующем терминале. В окружении Windows с WSL адрес страницы тот же.

`nginx -p "$PWD/" -c nginx.conf` задаёт каталог проекта как префикс.
Поэтому `root site` указывает на папку страницы, а служебные файлы находятся
в `.run`. Nginx запускается от обычного пользователя.

## API

| Метод и путь | Ответ |
| --- | --- |
| GET /apihealth | 200 и `{"status":"ok"}` |
| GET /api/tasks | 200 и JSON-массив задач |
| POST /api/tasks | 201 и созданная задача |

Название задачи содержит от 1 до 200 символов после удаления пробелов по краям.
Неверные данные возвращают HTTP 422. Список хранится в памяти одного процесса
и очищается при перезапуске. Несколько workers для этого варианта не применяются.

```bash
curl http://localhost:8085/apihealth
curl -i http://localhost:8085/api/tasks \
  -H 'Content-Type: application/json' \
  -d '{"title":"Подготовить отчёт"}'
curl http://localhost:8085/api/tasks
```

Путь `/apihealth` сохранён ровно как в задании. Для него предусмотрен отдельный
`location = /apihealth`. Префикс `/api/` проксируется без удаления части пути:
в `proxy_pass` после адреса приложения нет завершающего `/`.

## Проверки

```bash
uv run --locked pytest -q
uv run --locked python scripts/check_nginx.py
```

Вторая проверка запускает собственные процессы приложения и nginx. Перед ней
нужно остановить демонстрационный запуск, чтобы порты 8005 и 8085 были свободны.
Проверяются страница, ресурсы, API, привязка приложения к loopback и поведение
после остановки приложения: файлы сайта доступны, а API возвращает 502.
По завершении проверки её процессы останавливаются.
